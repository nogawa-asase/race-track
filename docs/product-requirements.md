# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**レーストラック** - 方眼紙のカーレースを、ブラウザでCPUと対戦

### プロダクトコンセプト
- **ブラウザを開くだけ**: 方眼紙もペンも対戦相手もいらない。PCでもスマホでも、URLを開けばすぐに1レース遊べる
- **判定はぜんぶおまかせ**: コースのはみ出し・衝突・加減速の制限をゲームが自動で判定し、選べる点だけを示す。ルールを覚える前から遊べる
- **「慣性」が目で見える**: 慣性点とそのまわりの9候補を盤に重ねて表示し、「車は急に止まれない・急に曲がれない」を遊びながら体で理解できる

### プロダクトビジョン
『マーチン・ガードナーの数学ゲームⅡ 新装版』(別冊日経サイエンス182)の第17話「シムとチョンプとレーストラック」で紹介された紙と鉛筆のゲーム「レーストラック」を、ブラウザだけで遊べるようにする。
サイコロを使わず、慣性だけで勝負が決まるこのゲームの面白さを、まずはCPUとの1対1で手軽に味わえるようにする。
全状態を探索した手ごわいCPUと、手加減してくれるCPUを用意し、数学パズル好きの大人から学生までが自分に合った相手と遊べるようにする。
記事の図のような「黄緑の芝に白い方眼、赤鉛筆と青鉛筆の軌跡」の雰囲気を再現する。
将来的には、離れた相手ともオンラインで対戦できるようにする。

### 目的
- 紙で遊ぶための準備(方眼紙・コース作り・ペン・相手探し)をなくし、記事を読んだ人がすぐに試せるようにする
- ルールの判定を自動化し、数え間違いや判定をめぐる揉めごとをなくす
- 9候補の表示で、文章では分かりにくい「加速・減速は1手に1目盛りまで」のルールを直感的に伝える
- CPU対戦で、相手がいなくても1人で張り合いのある勝負ができるようにする

## ゲームのルール

このゲームが実装するルールの正式な定義。機能要件の判定はすべてこの定義に従う。

### 準備
- 方眼紙の上にコースが描かれている。片方の端がスタートライン、もう片方の端がゴールライン
- 車は格子点(方眼の線の交点)の上だけを動く
- 先攻後攻を決め、手番順にスタートライン上の格子点を1つ選んで車を置く。相手の車がある点は選べない
- はじめの速度は0(縦0・横0)

### 1手の進め方
交互に1手ずつ、自分の車を新しい格子点へ進め、元の点と線で結ぶ。行き先は、次の3つの条件をすべて満たす点から選ぶ。

1. **コースからはみ出さない**: 行き先の格子点も、そこまでの線分も、コースの内側になければならない(ゴールする手を除く。後述)
2. **相手の車がいる点には止まれない(衝突禁止)**: 禁止されるのは同時に同じ点にいることだけ。線どうしの交差や、相手が以前いた点に止まるのは許される
3. **加速・減速は1手に1目盛りまで**: 前の手の移動量が縦 k・横 m のとき、今回の移動量 k'・m' は |k − k'| ≤ 1 かつ |m − m'| ≤ 1。すなわち、前の手とまったく同じだけ進んだ点(**慣性点**)を中心とする3×3の9点(**候補**)のどれか

### ゴールと勝敗
- 1手の線分がゴールラインに到達または通過したらゴール。ゴールライン上にぴったり止まった場合もゴールとする
- ゴールする手に限り、線分がゴールラインの先(コースの外)に出てもよい。ただし、ゴールラインに到達するまでの部分はコースの内側になければならない
- 先攻の手とそれに続く後攻の手を合わせて1**周回**と呼ぶ
- 先にゴールした方の勝ち。ただし、同じ周回で両者がゴールした場合は後攻の勝ち(**同着ルール**)。そのため、先攻がゴールしてもすぐにはレースを終えず、その周回の後攻の手番まで続ける
- 自分の手番で9候補がすべて選べないときは、その時点で負け(**行き止まり**。詳しくは下の「このゲームで決めたこと」)
- サイコロなどの運の要素はない。選べない点は最初から選べないため、反則はない

### このゲームで決めたこと(記事に明記がない部分と、記事から変えた部分)
- **行き止まりは負け**: 自分の手番で9候補がすべて選べないときは負けとする(記事には、この場合の扱いが書かれていない)。理由がコースの外でも、相手の車に塞がれている場合でも同じ。次の順に知らせる
  1. 次の手番で9候補がすべてコースの外になる点に移動したとき、その場で「次の手番では、どこにも進めません」というメッセージを表示する(相手の車が理由の場合は、相手が動けば進める可能性があるため、このメッセージは出さない)
  2. その車の次の手番で、9候補がすべて選べないことを盤に表示してから、負けを表示する
- **その場にとどまる手**: 速度0のとき、同じ点にとどまる手(縦0・横0)も認める。そのため、速度0のときは行き止まりにならない
- **スタート位置**: 手番順に、スタートライン上の好きな格子点を選ぶ
- **とどまり続ける手**: 速度0でその場にとどまる手を続けることに制限は設けない(抜けたいときは「設定に戻る」を使う)
- **同着は後攻の勝ち**: 記事では先に通過した先攻の勝ちだが、後攻はスタート位置を後から選ぶなど不利なため、同じ手数でゴールした後攻を勝ちとする

- **期待する解決策**: ルールどおりに正しく判定してくれる盤と、本気で考えないと勝てない手ごわいCPU。記事の図のような方眼紙と鉛筆の雰囲気
- **典型的な利用シーン**: 平日の夜、PCのブラウザで「つよい」CPUに挑み、1レース5分ほどで何度か繰り返す。うまくいった軌跡を眺めて最短ラインを考える

### セカンダリーペルソナ: 高橋 美咲(13歳、中学生)
- ちょっとした頭脳ゲームが好き。スマホやタブレットのタップ操作に慣れている
- 長いルール説明を読むのは苦手

- **期待する解決策**: 行ける点が示され、タップするだけで遊べる。手加減してくれる「よわい」CPUと、危ない手を教えてくれる行き止まりのアラート。1回が5分くらいで終わる
- **典型的な利用シーン**: 休み時間や家で、スマホのブラウザから「よわい」CPUと対戦する。慣れてきたら、1台のスマホを友だちと交互に使って人同士で対戦する

## 成功指標(KPI)

最初の版ではデータを保存せず、サーバーも使わないため、利用状況のアクセス解析は行わない。指標は、自動テストと少人数のプレイテストで測定する。

### プライマリーKPI
- **ルール判定の正しさ**: 「ゲームのルール」の各規則(はみ出し・衝突・加減速・ゴール・行き止まり・同着)を検証する自動テストがすべて合格する(最初の版の公開時)
- **分かりやすさ**: ルール説明を読んでいない初プレイヤー5人中4人以上が、手助けなしで1レースを最後まで遊べる(最初の版の公開前のプレイテストで測定)
- **テンポ**: 初プレイヤーのCPU戦1レース(設定画面から結果表示まで)の所要時間の中央値が5分前後(3〜7分)に収まる(同プレイテストで測定)

### セカンダリーKPI
- **手応え(よわい)**: 初プレイヤー5人中4人以上が、「よわい」に3レース以内で1勝できる(同プレイテストで測定)
- **手応え(つよい)**: 初プレイヤー5人が各3レース「つよい」に挑んだとき、勝ち数の合計が15レース中5以下になる(同プレイテストで測定)
- **CPUの正確さ(つよい)**: 「つよい」は、どのコースでも各状態で理論最短の手を指す(自動テストで確認)
- **CPUの行き詰まりゼロ**: 全コース・全強度の組み合わせで、CPU同士の対戦シミュレーションを各100レース以上行い、すべてのレースが決着し、CPUが自分から行き止まりに進んで負けることがない(最初の版の公開時)
- **動作環境**: 対応環境(非機能要件を参照)のPCとスマホの両方で、1レースを最後まで遊べる(最初の版の公開時に手動確認)

## 機能要件

### コア機能(MVP)

#### 1. ルール判定

**ユーザーストーリー**:
プレイヤーとして、数え間違いや判定をめぐる揉めごとなく遊ぶために、ゲームが毎手のルール判定を自動で行ってほしい

**受け入れ条件**:
- [ ] 手番のたびに、慣性点のまわり9点をそれぞれ「選べる」「ゴールできる」「選べない(はみ出す)」「選べない(相手がいる)」のいずれかに分類する
- [ ] 行き先の格子点と、そこまでの線分の両方がコース内のときだけ「選べる」とする。カーブの内側の芝を横切る線分は「はみ出す」とする
- [ ] 相手の車が現在いる点は「相手がいる」とする。相手が以前いた点や、相手の軌跡と交差する線分は妨げない
- [ ] 線分がゴールラインに到達または通過する点は、ゴールライン通過後にコースの外へ出ていても「ゴールできる」とする。ゴールライン上にぴったり止まる点も「ゴールできる」とする
- [ ] 速度0のとき、その場にとどまる点(中央)も候補に含める。方向パッドの中央(「そのまま」)も選べる
- [ ] 移動した先の点で、次の手番の9候補がすべてコースの外になるときは、その場で「次の手番では、どこにも進めません」というメッセージを表示する
- [ ] 手番の開始時に選べる点・ゴールできる点が1つもないときは、9候補がすべて選べないこと(それぞれの理由)を盤に表示してから、その手番のプレイヤーの負けとする
- [ ] 先攻がゴールしたときは、同じ周回の後攻の手番まで続ける。後攻もその手でゴールしたら後攻の勝ち、しなければ先攻の勝ちとする(後攻が行き止まりの場合も先攻の勝ち)
- [ ] 判定と盤の見た目のずれは0.1目盛り未満

**優先度**: P0(必須)

#### 2. 9候補の表示と選択

**ユーザーストーリー**:
プレイヤーとして、ルールを覚えていなくても次の1手を選べるように、行ける点が盤の上に示され、それを選ぶだけで進められるようにしてほしい

**受け入れ条件**:
- [ ] 手番のプレイヤーの慣性点と9候補を盤の上に重ねて表示する
- [ ] 「選べる」「ゴールできる」「はみ出す」「相手がいる」の4種類を、色と記号の両方で区別する(色だけに頼らない)
- [ ] 「はみ出す」「相手がいる」の点は選択できない
- [ ] マウスでは、候補の点を1回クリックすると確定する
- [ ] タッチ操作では、1回目のタップで行き先と線分をプレビュー表示し、同じ点への2回目のタップで確定する
- [ ] 盤とは別に、3×3の方向パッド(中央は「そのまま」)で候補を選べる。1回目の押下で行き先と線分をプレビュー表示し、同じボタンの2回目の押下で確定する。選べない方向のボタンは無効化して表示する
- [ ] 確定すると、車が元の点から行き先まで移動するアニメーションを表示し、元の点と行き先を手番のプレイヤーの色の線で結ぶ

**優先度**: P0(必須)

#### 3. 1対1の対戦(CPUまたは人)

**ユーザーストーリー**:
プレイヤーとして、相手がいないときでも張り合いのある勝負をするために、自分の腕前に合った強さのCPUと対戦したい。また、そばにいる人とも1台の端末で対戦したい

**受け入れ条件**:
- [ ] 対戦相手として「CPU(青)」か「人」を選べる。デフォルトは「CPU(青)」
- [ ] 「人」を選んだ場合は、1台の端末で2人が交互に操作する
- [ ] 人同士は、先攻を赤鉛筆、後攻を青鉛筆の色で表示する。CPU戦は、先攻後攻によらずCPUがいつも青鉛筆(人が赤鉛筆)になる。手番のプレイヤーを色と文字の両方で常に表示する
- [ ] CPUの強さの設定は、対戦相手が「CPU」のときだけ表示する
- [ ] CPUの強さは「よわい」「ふつう」「つよい」の3段階。デフォルトは「ふつう」
- [ ] CPUは、全状態(位置と速度の組み合わせ)についてゴールまでの最短手数を求め、それをもとに指す。この先どう指してもゴールできない状態(いずれ行き止まりになる状態)は、最短手数を「なし」とする
- [ ] 最短手数は、相手の車がない前提で計算する
- [ ] 「つよい」は、常に最短手数が最小になる手を指す。その点が相手の車で塞がれているときは、次に最短手数が小さい手を指す
- [ ] 「ふつう」と「よわい」は、一定の確率で最短ではない手を混ぜて指す。「よわい」の方が混ぜる頻度と損の大きさが大きい(具体的な確率はプレイテストで調整する)
- [ ] どの強さでも、ゴールできる手があれば必ずゴールする
- [ ] どの強さでも、ほかに選択肢がある限り、最短手数が「なし」の手(この先どう指しても行き止まりになる手)は選ばない
- [ ] CPUはスタート位置も自動で選ぶ
- [ ] CPUの手番では、指す前に一呼吸置く(表示はしない。間の長さは非機能要件の「パフォーマンス」)

**優先度**: P0(必須)

#### 4. コース3つ

**ユーザーストーリー**:
プレイヤーとして、腕前に合わせて繰り返し楽しむために、難しさの異なる複数のコースから選びたい

**受け入れ条件**:
- [ ] 次の3コースを用意し、設定画面で選べる。デフォルトは「ヘアピン」

  | コース | 難易度 | 特徴 |
  |--------|--------|------|
  | ヘアピン | やさしい | 幅広。大きなヘアピンが2つ |
  | クランク | ふつう | 直角カーブの切り返しが続く |
  | うずまき | むずかしい | 細いコースが内側へ締まっていく |

- [ ] 設定画面で、各コースの形のプレビューと難易度を表示する
- [ ] 各コースは、コースの別々の部分の間に2目盛り以上の芝がある(自動テストで確認)
- [ ] 各コースで、全スタート位置からゴールまでの最短手数が「なし」にならない(自動テストで確認)
- [ ] コースは芝(黄緑)の上に白い方眼で描き、スタートラインとゴールラインをはっきり示す

**優先度**: P0(必須)

#### 5. ゲームの流れ

**ユーザーストーリー**:
プレイヤーとして、迷わずにレースを始めて終えるために、設定からスタート位置選び、レース、結果までが一続きの流れになっていてほしい

**受け入れ条件**:
- [ ] 次の順に画面が進む
  ```text
  設定(対戦相手〔CPU/人〕・コース・CPUの強さ・先攻後攻)
    → くじで先攻後攻を決める(CPU戦で「くじ」を選んだ場合)
    → スタートライン上の位置を手番順に選ぶ
    → レース(交互に1手ずつ)
    → 結果(勝敗・手数)
  ```
- [ ] CPU戦では、先攻後攻を「くじ」「先攻」「後攻」から選べる。デフォルトは「くじ」
- [ ] 人同士の対戦では、くじを行わず「赤鉛筆が先攻です」と表示する(2人は色で呼び分けるため、どちらが赤鉛筆を持つかは2人で決める)
- [ ] くじの結果(どちらが先攻か)を画面に表示してから、スタート位置選びに進む
- [ ] スタート位置選びでは、スタートライン上の選べる格子点を示し、相手の車がある点は選べない
- [ ] スタート位置は、盤への直接クリック・タップ(マウス・タッチとも1回で確定)で選ぶ(キーボード操作はP1の「10. キーボード操作」で対応)
- [ ] レース中は、現在のターン数と手番のプレイヤーを表示する
- [ ] 結果画面では、勝者・両者の手数・決着の理由(ゴール/同着ルール/行き止まり/リタイヤ)を表示する
- [ ] 結果画面から「同じ設定でもう一度」と「設定に戻る」を選べる
- [ ] レース中いつでも「設定に戻る」ことができる(確認を挟む)
- [ ] レース中いつでも「リタイヤ」できる(確認を挟む)。CPU戦では手番によらず人の負け・CPUの勝ちになり、人同士では今の手番のプレイヤーの負けになる

**優先度**: P0(必須)

#### 6. PCとスマホの両方で遊べる

**ユーザーストーリー**:
プレイヤーとして、手元の端末で気軽に遊ぶために、PCでもスマホでも同じように遊べるようにしてほしい

**受け入れ条件**:
- [ ] 画面幅によらず、盤の下に操作パネル(手番表示・ボタン)を縦に並べる(PC・スマホで同じ見た目にする)
- [ ] 幅360px以上の画面で、横スクロールなしで盤の全体が表示される
- [ ] 盤への直接クリック・タップ(1回で確定)で操作できる
- [ ] 盤のタップ判定は、タップしやすい大きさにする
- [ ] アプリストアでの配信は行わず、ブラウザで遊ぶ形とする

**優先度**: P0(必須)

#### 6-2. ルール説明

**ユーザーストーリー**:
プレイヤーとして、遊びながら疑問が出たときにルールを確かめられるように、いつでもルール説明を開きたい

**受け入れ条件**:
- [ ] 設定画面と、スタート位置選び・レース中の画面から「ルール説明」を開ける
- [ ] 内容は、本書の「ゲームのルール」の要点(急な加減速はできないこと、慣性点を中心に1マス分だけ調整できること、相手より先にゴールを目指すこと、同じマス目に2台止まれないこと、同着は後攻の勝ちになること)を、短い文章数個と慣性点の図で分かりやすく伝える(細部まで網羅する説明ではない)
- [ ] スクロールなしで1画面に収まるようにする(端末で収まらない場合のみ、スクロールできるようにする)
- [ ] ルール説明を開いている間は、CPUの手番も進めない。閉じると元の画面に戻り、続きから遊べる
- [ ] 読まなくても遊べる(ルール説明を開くことを求めない)

**優先度**: P0(必須)

### 初期リリース後すぐに追加する機能

#### 7. 行き止まりのアラート

**ユーザーストーリー**:
初心者のプレイヤーとして、行き止まりで負けないように、選ぶと行き止まりになる危ない手を事前に知りたい

**受け入れ条件**:
- [ ] 設定でアラートのオン/オフを切り替えられる。デフォルトはオン
- [ ] オンのとき、選ぶと次の手番で行き止まりになる候補を選択(クリック・タップ)すると、移動する前に「次の手番では、どこにも進めません」というメッセージを表示し、移動しない
- [ ] メッセージを閉じると、その候補はバツ(選べない候補と同じ表示)になる。他の候補は選べるままなので、選び直せる
- [ ] 判定では相手の車を考えない
- [ ] 判定は次の手番の9候補がすべてコースの外になるかどうかだけで行い、数手先までの探索は行わない(オフのときの事後メッセージと同じ判定)

**優先度**: P1(重要)

#### 8. 1手戻す(待った)

**ユーザーストーリー**:
プレイヤーとして、操作ミスや悪手をやり直すために、1手戻したい

**受け入れ条件**:
- [ ] CPU戦では、自分の直前の1手と、それに対するCPUの応手をまとめて戻す
- [ ] 人同士の対戦では、直前の1手を戻す
- [ ] 両者がスタート位置に車を置いた直後まで、連続して戻せる(スタート位置の選び直しはしない)
- [ ] 結果画面に進んだ後は戻せない

**優先度**: P1(重要)

#### 9. 表示の切り替え

**ユーザーストーリー**:
プレイヤーとして、見やすく遊ぶために、表示を好みや端末に合わせて切り替えたい

**受け入れ条件**:
- [ ] 軌跡の各点に手数の番号を表示できる(記事の図のように)。デフォルトは表示しない
- [ ] スマホ向けに、手番の車を中心に盤を拡大表示するモードに切り替えられる。デフォルトはオフ(盤全体を表示)
- [ ] ダークモードに対応する。デフォルトは端末の設定に従い、手動でも切り替えられる

**優先度**: P1(重要)

#### 10. キーボード操作

**ユーザーストーリー**:
PCのプレイヤーとして、マウスを使わずにテンポよく指すために、キーボードで候補を選びたい

**受け入れ条件**:
- [ ] テンキー(7 8 9 / 4 5 6 / 1 2 3)と、Q W E / A S D / Z X C の両方で、3×3の候補を選べる(5・S は「そのまま」)
- [ ] キーを押すと、その候補をプレビューし、Enterで確定する
- [ ] 選べない候補のキーを押しても何も起こらない
- [ ] スタート位置選びでは、← → で選び、Enterで確定する

**優先度**: P1(重要)

#### 11. 言語切り替え

**ユーザーストーリー**:
日本語を読めないプレイヤーとして、このゲームで遊ぶために、画面を英語に切り替えたい

**受け入れ条件**:
- [ ] 画面の同じ場所(右上)にある切り替えボタンで、日本語⇔英語をいつでも切り替えられる。ボタンには切り替えた先の言語名を表示する(今が日本語なら「English」、今が英語なら「日本語」)
- [ ] 設定画面・レース画面・結果画面・ルール説明・確認やメッセージのダイアログなど、画面内のすべての文言(ロゴ、ボタン、ラベル、選択肢、メッセージ)が対象になる
- [ ] 設定(対戦相手・コース・CPUの強さ・先攻後攻・行き止まりのアラート)の選択は、切り替えても保たれる
- [ ] レースの途中で切り替えても、今の手番や進行中の状態はそのまま、表示の文言だけが切り替わる
- [ ] 設定と同じく、ページを開き直すと既定(日本語)に戻る(保存しない)

**優先度**: P1(重要)

### 将来的な機能(Post-MVP)

#### 11. オンライン対戦
itch.io上で、離れた相手と人同士で対戦できるようにする。itch.ioには対戦用のサーバーがないため、Firebaseのようなリアルタイム同期サービスを別に用意してつなぐ。ターン制で、1手ごとに送るのは座標だけ。取りかかるのは、「12. 人数を増やす」が完成してから。

**優先度**: P2(できれば)

#### 12. 人数を増やす
3台以上でのレースと、1人でのタイムアタック。P1が完成した後、オンライン対戦より前に取り組む。対応するときは、最大台数、同着ルールの扱い、行き止まりになった車の扱い(その車だけ脱落など)、3台目以降の鉛筆の色、CPUと人の組み合わせを決める。

**優先度**: P2(できれば)

#### 13. コースを増やす
まずは固定コースを追加する。ランダム生成(芝の幅や自己交差の自動チェックが必要)と、自分でコースを描けるエディタは、その後に検討する。

**優先度**: P2(できれば)

#### 14. リプレイと共有
対戦記録の保存と再生、記事の図のような軌跡の画像書き出し、CPUの最短ライン(お手本)の表示。

**優先度**: P2(できれば)

## 非機能要件

### パフォーマンス
- コースの準備(CPU用の最短手数の表の用意): 0.1秒程度、最大でも1秒以内。スマホの目安として、PCのブラウザでCPUを4倍遅くした条件で測る(測定方法は `docs/architecture.md` の「パフォーマンス要件」)
- CPUの手の計算: 50ms以内。指す前に約0.5秒の間を置く(表示はしない)
- 車の移動アニメーション: 約0.26秒で、なめらか(目標60fps)に表示する
- 候補の表示: 手番が移ってから100ms以内に表示される
- 初回表示: 一般的なモバイル回線(下り1.6Mbps・遅延150ms程度)で3秒以内に遊べる状態になる(測定方法は `docs/architecture.md` の「パフォーマンス要件」)

### ユーザビリティ
- ルール説明を読まなくても、候補の表示だけで1レースを最後まで遊べる
- 行き止まりで負けるときは、いきなり負けにせず、行き止まりの点に移動した時点でメッセージで知らせ、次の手番で9候補が選べないことを盤で見せてから負けにする
- 候補の種類は、色覚に関わらず区別できるよう、色と記号を併用する
- 動きを減らす設定(prefers-reduced-motion)が有効なときは、アニメーションを省略または短縮する
- ルール説明はいつでも開けるようにする(読まなくても遊べるが、読みたい人のために用意する)

### 信頼性
- ルール判定は「ゲームのルール」の定義と完全に一致する(自動テストで確認)
- CPUは行き詰まらない(CPU同士の対戦シミュレーションで確認)
- コースの別々の部分の間には2目盛り以上の芝がある(自動テストで確認)
- 判定と見た目のずれは0.1目盛り未満

### セキュリティ
- 最初の版では、個人情報を含むデータを一切収集・送信しない
- 外部サーバーとの通信を行わない(itch.ioからの静的ファイルの配信のみ)
- 外部スクリプトやトラッキングを読み込まない

### スケーラビリティ
- 盤の大きさは、幅360pxの画面で盤全体が横スクロールなしで表示でき、コースの準備が1秒以内に終わる範囲で決める(具体的な値はアーキテクチャ設計書で定める)
- CPUの探索は、そのコースで出せるすべての速度を扱う(自動テストで確認)
- 3台以上のレースとオンライン対戦(P2)を追加するときに作り直さずに済むよう、ゲームの状態と1手の表現は画面表示から独立させ、プレイヤーの人数を2人に固定しない

### 対応環境
- 公開先: itch.io(HTML5ゲームとしてブラウザで遊べる形で公開する)
- PC: 最新版の Chrome / Edge / Firefox / Safari
- スマホ: iOS Safari・Android Chrome の最新版
- 画面幅360px以上

## スコープ外

明示的にスコープ外とする項目(最初の版):
- オンライン対戦とアカウント機能
- 3台以上でのレース、タイムアタック
- コースの追加・ランダム生成・エディタ
- 対戦記録の保存、リプレイ、画像の書き出し
- スマホアプリ化(App Store・Google Playでの配信)
- データの保存(設定の記憶を含む)とサーバーの利用
- アクセス解析

## 決定事項(アイデアメモの「今後の検討事項」から)

- **公開先**: 最初の版からitch.ioで公開する
- **開発の順番**: 最初の版(P0。1対1) → P1 → 3台以上に増やす → オンライン対戦
- **コースの増やし方**: まずは固定コースを増やす
